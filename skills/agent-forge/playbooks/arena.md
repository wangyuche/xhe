# Playbook:arena(不確定設計方向時)

依據:pstack 的 `arena` 原文。非瑣碎的產出,一次嘗試可能把形狀鎖錯時使用。

1. **框定:** 每個候選拿到同一份提示;先定 3 到 6 條可評分的標準;每個候選有自己的輸出位置。
2. **扇出:** 一次派出 N 個,各自產出並附上「拒絕了哪些替代方案」。有人沒產出就用 N-1 個繼續。
3. **交叉評審:** 另派一個只讀的評審,模型家族要和上層不同,逐條標準打分並推薦基底。候選還在寫時不要派評審。
4. **選基底:** 自己讀完每個候選,逐條標準打分,不憑整體感覺。選「之後的維護者最容易擴充又不破壞不變量」的那個;平手時選邊界更乾淨、API 更小的。評審同意就是確認,不同意代表有人有偏見或標準含糊。
5. **嫁接:** 通常每個落選者只取一到兩個優點,用手整合,不要貼上。候選趨於一致就直接採用共識;差異極大就重新框定再跑,不要取平均。
6. **驗證:** 整合後的成品要像任何產出一樣驗證。驗證發現漏掉的問題,就回到框定或嫁接。

回報:選了哪個基底和理由、評審的結論(或說明沒有評審)、每項嫁接及來源、拒絕了什麼和理由、中途退出者、驗證結果。
