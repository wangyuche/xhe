# 專業 agent 範本

agent-forge 在 Spec 與 Build 階段使用。分兩部分:規格區(階段 2 填寫)和 agent 本體範本(階段 3 套用)。

---

## 規格區

存到 `.claude/agent-specs/<agent-name>.md`。

```markdown
# <agent-name> 規格

## 一句話定位
<這個 agent 是誰、替誰做什麼>

## 做什麼
- ...

## 不做什麼
- ...

## 觸發時機
<什麼情況下該呼叫它>

## 輸入
<它會拿到什麼>

## 輸出
<格式、結構、長度;附一個範例>

## 成功標準
每條都必須能被實際檢查。
1. ...
2. ...

## 限制與禁忌
- ...

## 工具
| 工具 | 為什麼需要 |
|---|---|
| Read | ... |

## 停止並詢問的情況
- ...

## 語言與語氣
<預設繁體中文;語氣要求>

## 協作
- 角色:owner(寫入者)/ verifier(驗證者)/ 協調者 / 只讀調查
- 是否會寫入檔案:是 / 否(否則不需要分支)
- 可寫路徑:<路徑或模式,供派工時檢查是否重疊>
- 不可寫路徑與禁止動作:...
- 完成時要回報的證據:<PASS / ISSUES / BLOCKED 要附什麼>
- 可否與其他寫入 agent 平行:是(需獨立可寫輸出)/ 否
- 建議的模型與推理強度:...(verifier 要用和作者不同的模型家族)
- 需要的 skill:<技術規則 skill,例如 stack-react,用 `paths` 限定範圍;或固定計算腳本 skill,例如指標計算。依 `create-agent.md`「什麼時候要做 skill」判斷,填「無」時寫一句理由>
- 專案混用多種技術時:一個通用角色加多個技術 skill,不要一技術一個 agent
```

---

## agent 本體範本

存到 `.claude/agents/<agent-name>.md`。

```markdown
---
name: <agent-name>
description: <一句話說明做什麼,以及何時該呼叫它。要寫得讓主 agent 能判斷是否委派>
tools: <只列規格中需要的工具>
model: <sonnet 或其他,依任務複雜度>
---

你是 <角色>。<一句話講清楚職責與邊界。>

## 工作流程

1. <步驟>(完成條件:...)
2. <步驟>(完成條件:...)

## 輸出格式

<具體格式與範例>

## 成功標準

<從規格原樣複製,讓 agent 知道自己會被如何檢查>

## 限制

- <禁忌>

## 遇到以下情況要停下來問使用者

- <情況>
```
